4. adımı sen yaz ve yap

4. Adım: Read-model'i tutacak yeri belirlemek ve oluşturmak.

Karar: Ayrı bir "read-service" açmak yerine web-gateway içinde, öğrenci servisiyle aynı desende (database.py + models + repo) küçük bir SQLite tablosu tutuyoruz. Bu tablo öğrenci verisini city/department adlarıyla birlikte önceden birleştirilmiş (denormalize) halde saklar, böylece 5. adımda yazılacak consumer bu tabloyu güncel tutacak ve /students endpoint'i artık 3 servise gitmeden doğrudan buradan okuyabilecek.

4.1 — Dosya yapısı (web-gateway içinde, mevcut servislerle aynı desen)

web-gateway/
  database.py                              (Database context manager, diğer servislerle birebir aynı)
  models/
    base_model.py                          (BaseModel, diğer servislerle birebir aynı)
    student_read_model.py                  (StudentReadModel: id, name, surname, street, number, cityid, departmentid, cityname, departmentname)
  repo/
    base_repository.py                     (BaseRepository, diğer servislerle birebir aynı)
    student_read_model_repository.py       (create_table, upsert, delete, update_city_name, update_department_name, clear_city, clear_department, list_paginated, count)

4.2 — Tablo şeması

CREATE TABLE IF NOT EXISTS student_read_model (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    surname TEXT,
    street TEXT,
    number TEXT,
    cityid INTEGER,
    departmentid INTEGER,
    cityname TEXT,
    departmentname TEXT
)

id, öğrenci servisindeki student.id ile birebir aynı (foreign key değil, event'ten gelen id kullanılıyor) — bu sayede upsert idempotent olur.

4.3 — Repository metotları

- upsert(id, name, surname, street, number, cityid, departmentid, cityname, departmentname): INSERT ... ON CONFLICT(id) DO UPDATE — student.created/student.updated event'lerinde kullanılacak
- delete(id): student.deleted event'inde kullanılacak
- update_city_name(cityid, cityname): UPDATE ... SET cityname = ? WHERE cityid = ? — city.updated event'inde, o şehre bağlı TÜM öğrenci satırlarını cascade günceller
- update_department_name(departmentid, departmentname): aynı mantık, department.updated için
- clear_city(cityid): city.deleted event'inde cityname'i NULL yapar (öğrenci silinmez, sadece görünen şehir adı kaybolur)
- clear_department(departmentid): department.deleted event'inde departmentname'i NULL yapar
- list_paginated(limit, offset): sayfalı okuma (ileride /students endpoint'i bunu kullanacak)
- count(): toplam satır sayısı (sayfalama UI'ı için)

4.4 — DB dosyası ve docker-compose

Diğer servislerle tutarlı olması için READMODEL_DB_PATH env değişkeni ve ./data:/data volume'ü web-gateway servisine eklenir. Varsayılan yol: /data/student_read_model.db.

4.5 — Gateway başlangıcında tabloyu oluşturma

main.py'de FastAPI lifespan/startup içinde repository'nin create_table() metodu çağrılır, böylece container her ayağa kalktığında tablo yoksa oluşturulur (idempotent, IF NOT EXISTS).

Not: Bu adımda henüz hiçbir event tüketilmiyor (consumer yok) — sadece read-model'in DURACAĞI yer ve şema hazırlanıyor. Event'leri dinleyip bu repository'yi çağıracak consumer 5. adımda yazılacak.
