3. adımı bana step by step anlat

3. Adım: Producer tarafı — student-service, city-service, department-service'in create/update/delete işlemlerinde event yayınlaması.

Önemli bir not: Bu üç serviste endpoint'ler def (senkron), async def değil. Bu yüzden aio-pika yerine senkron pika kütüphanesini kullanacağız — event loop karmaşasına girmeden, mevcut kod stiliyle uyumlu.

Ayrıca bu üç servis birbirinden tamamen bağımsız (paylaşılan bir ortak paket yok), o yüzden aynı küçük publisher kodunu her birine ayrı ayrı ekleyeceğiz.

3.1 — requirements.txt'e pika ekleyin

Her üç serviste (services/student-service/requirements.txt, city-service/..., department-service/...) şu satırı ekleyin:
pika

3.2 — Her serviste events.py adında bir publisher modülü oluşturun

Örnek: services/student-service/events.py

import os
import json
import pika

RABBITMQ_URL = os.environ.get("RABBITMQ_URL", "amqp://guest:guest@localhost:5672/")
EXCHANGE_NAME = "domain.events"


def publish_event(routing_key: str, payload: dict) -> None:
    connection = pika.BlockingConnection(pika.URLParameters(RABBITMQ_URL))
    try:
        channel = connection.channel()
        channel.exchange_declare(exchange=EXCHANGE_NAME, exchange_type="topic", durable=True)
        channel.basic_publish(
            exchange=EXCHANGE_NAME,
            routing_key=routing_key,
            body=json.dumps(payload),
            properties=pika.BasicProperties(content_type="application/json", delivery_mode=2),
        )
    finally:
        connection.close()

- exchange_declare idempotent'tir (varsa dokunmaz), bu yüzden her publish'te çağırmak güvenli — exchange'i management UI'de elle silseniz bile kod kendini toparlar.
- delivery_mode=2 mesajı persistent yapar (RabbitMQ restart olsa da kaybolmaz).

Aynı dosyayı city-service/events.py ve department-service/events.py içine de kopyalayın — içerik birebir aynı kalabilir.

3.3 — main.py'de create/update/delete endpoint'lerine publish çağrısı ekleyin

student-service/main.py için:

from events import publish_event

@app.post("/students", response_model=StudentOut, status_code=201)
def create_student(data: StudentIn):
    new_id = repo.add(data.name, data.surname, data.street, data.number, data.cityid, data.departmentid)
    publish_event("student.created", {"id": new_id, **data.model_dump()})
    return StudentOut(id=new_id, **data.model_dump())


@app.put("/students/{id}", response_model=StudentOut)
def update_student(id: int, data: StudentIn):
    if repo.find(id) is None:
        raise HTTPException(status_code=404, detail="not found")
    repo.update(id, data.name, data.surname, data.street, data.number, data.cityid, data.departmentid)
    publish_event("student.updated", {"id": id, **data.model_dump()})
    return StudentOut(id=id, **data.model_dump())


@app.delete("/students/{id}", status_code=204)
def delete_student(id: int):
    repo.delete(id)
    publish_event("student.deleted", {"id": id})

city-service/main.py ve department-service/main.py'de aynı mantık, sadece routing key'ler city.created/updated/deleted ve department.created/updated/deleted olacak, payload da o servisin alanlarını içerecek (örn. sadece {"id": id, "name": name}).

3.4 — Dockerfile'ları kontrol edin

requirements.txt değiştiği için image'ların yeniden build edilmesi gerekecek — Dockerfile'da RUN pip install -r requirements.txt zaten var olduğu için ekstra değişiklik gerekmez.

3.5 — Yeniden build edip ayağa kaldırın

docker compose up -d --build student-service city-service department-service

3.6 — Test edin

Gateway üzerinden (veya doğrudan POST http://localhost:8005/students gibi) yeni bir öğrenci ekleyin, sonra RabbitMQ management UI'de (http://localhost:15672) student-read-model-queue'nun Messages sayısının arttığını kontrol edin — bu, publish'in gerçekten çalıştığının kanıtı.
